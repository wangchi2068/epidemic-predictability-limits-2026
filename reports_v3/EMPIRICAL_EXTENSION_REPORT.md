# 实证扩展报告：三赛季版本化外部审计

> **Deprecated 提示**：本报告包含早期机制预测器加入严格四方交集过滤之前的历史汇总草稿（部分单元数为 1,428），不作为当前 32 页投稿稿的数值依据。当前论文正文表 6 与表 7 采用严格四方共同单元交集（三模型共享相同样本量：2023--24 季 $n=1{,}337$；2024--25 季 $n=1{,}315$；2025--26 季 $n=1{,}376$），权威数值结果以 `reports_v3/flusight_v1.*_extended.json` 及正文为准。

**目标**：把重构稿的外部审计从两个赛季扩到三个，并把评分维度从 WIS/MAE 扩到完整评分面板，同时把论文自己的机制基准放到**同一批预测单元**上评分，量化"机制基准与业务预测之间的校准差距"。

**边界（必须遵守）**：所有预测均为 **final-vintage**（最终版真值），不是实时信息集下的评估；本文不把结果称为"验证"或"上界"；不涉及跨尺度的机制因果主张。

## 4. 这对论文意味着什么

第一，**"校准差距"从一句定性描述变成了三个独立赛季的量化结果**：机制基准不是一个可用的预测器，它的 95% 区间只覆盖约一半的真值，且在每个赛季都劣于官方 baseline。这正是论文需要的诚实结论，而且它不需要任何跨尺度机制主张——纯粹是同一批单元上的配对评分。

第二，**上升期崩塌给出了一条新的、可复现的经验规律**，且与论文的过程方差框架一致（成长期均值最难建模，风险累积最快）。它同时提示了一个真实的可操作含义：在疫情上升期，无论集成还是官方基线都不应被当作可靠区间来用。

第三，三个赛季的一致性（而不是一个赛季的偶然）让外部审计从"示例"升级为"证据"。v1.2.0 尤其重要：它是完全独立的赛季，且事前没有参与任何设计选择。

## 5. 局限

- 全部为 final-vintage 评估，使用修订后的真值；实时可得信息下的表现会更差，本文不做实时主张。
- 机制基准是**事后拟合**的基准（用 `reference_date − 7 天` 截断的最终真值拟合），它作为预测器的评分应读作"把机制模型当预测器用会怎样"，而不是它的理论最优表现。
- 上升期单元数少（153–1200），其覆盖率估计的区间较宽。
- v1.1.0 缺 2025-01-25 一个 origin（release 中即缺失，未插补）；三个 release 的提交模型构成不同。
